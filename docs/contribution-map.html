What can be shared

Product roadmap · 29 reuse candidates. The CoMaps/GNOME Maps comparison and regional MOTIS investigation proceed separately. Early transit, places and imagery discovery need no phone-navigation release.

A shared app or engine can cover map data and trip planning. Permissions, location, touch, audio and sleep still need platform adapters and physical tests. A model that cannot run the host OS remains blocked upstream.

How a change lands

The initial owner is temporary custodian. Ordinary merges wait until independent reviewers accept responsibility. AI compute and map-service operating budgets remain separate.

Where this started

Omamesh, Omastorm, Phonechy and Omarchy Mobile are the named inspirations. Their projects have not endorsed or joined this initiative. Existing applications and components get evaluated before a new client or fork.

Primary sources and reuse decisions
  • omamesh — Scuttle bounded coordinate/QML patterns; no code imported. MIT; GitHub API checked today
  • omastorm — Scuttle Rust/QML boundary, data freshness and pinned engine delivery. MIT; GitHub API checked today
  • phonechy — Learn touch experience; verify source/license before reuse. Source license not established
  • omarchy-mobile — Scuttle device profiles/location integration; kernel ownership upstream. Mixed per-file/kernel; inspect each part
  • comaps — Reuse/integrate before considering fork. Inspect component licenses and AI contribution rules
  • comaps-product — Learn existing offline search/routing. Product docs
  • gnome-maps — Compare existing desktop app. Inspect GPL/dependency licenses
  • omamap — Scuttle Qt/WebEngine/Leaflet GIS ideas. MIT in prior inspection; recheck
  • omarchy-earth — Learn profile-discriminating tests. MIT in prior inspection; recheck
  • omakeel — Scuttle GPS/AIS service boundary if useful. MIT in prior inspection; recheck
  • osm-tiles — No public-endpoint offline packs/bulk prefetch. Service policy
  • nominatim — No generic public endpoint default or autocomplete. Service policy
  • android-location — Use native permission/lifecycle contract. Official docs
  • web-location — Foreground browser fallback candidate. W3C specification
  • asahi — Model-specific OS prerequisite. Upstream support
  • github-rules — Verify live enforcement. Official docs
  • github-actions — Read-only, pinned actions; no untrusted execution in privileged job. Official docs
  • motis — Compare integrated regional service before adding separate engines. MIT listed upstream; inspect selected revision
  • otp — Transit alternative only for a demonstrated comparison need. LGPL; inspect components at selected revision
  • valhalla — Dedicated route comparator when integrated planning leaves an unmet case. Inspect selected code and graph/data licenses
  • photon — Search comparator when existing app/MOTIS is insufficient. Inspect selected code and data licenses; demo service terms separate
  • maplibre-js — Potential comparison surface, not selected product shell. Inspect selected renderer/dependency licenses
  • protomaps — Candidate matching tile-generation/style pipeline. Inspect schema/style/font/data licenses separately
  • pmtiles — Candidate display archive only. Archive specification; source data rights separate
  • bc-transit — Kelowna proposed static/alerts/updates/positions discovery. Agency terms apply; not CC0
  • bc-transit-terms — Record terms and attribution for the accepted experiment. Conditional, revocable agency terms; no acceptance asserted
  • gtfs-validator — Use static schedule validation separately from itinerary tests. Inspect selected validator/license
  • overture-places — Candidate regional place-data comparison. Source/theme-specific licensing and attribution
  • panoramax — Candidate imagery viewer with explicit coverage/capture-date states. Software, instance and image terms differ
  • drivebc-open511 — Road-event overlay candidate before route impact. API terms and data rights need accepted review
